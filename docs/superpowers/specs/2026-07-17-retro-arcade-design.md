# Retro Arcade — 经典小游戏合集设计文档

日期：2026-07-17
状态：已与用户逐节确认

## 1. 目标与背景

一个包含 8 款经典小游戏的网页游戏合集，目的有二：

1. **作品集展示** —— 有一定打磨度，可放到线上给他人看，仓库与演示链接一起展示。
2. **给家人朋友玩** —— 发一个链接即可玩，手机与电脑都要有良好体验。

界面语言为中文（代码、标识符、commit 为英文）。

## 2. 游戏清单（8 款）

| 分类 | 游戏 |
|------|------|
| 动作反应 | 贪吃蛇、俄罗斯方块、打砖块、Flappy Bird |
| 益智数字 | 2048、扫雷、数独 |
| 棋类对弈 | 五子棋（双人同屏 + 人机） |

## 3. 技术路线

**Vite + TypeScript，无框架**（已对比 React 与 Phaser 后选定）：

- 外壳（游戏中心）为普通 DOM；8 款游戏本体运行在 Canvas 上。
- 纯静态 SPA，hash 路由（`#/`、`#/snake` 等），GitHub Pages 刷新不 404。
- 决策记录：当前外壳 UI 简单（卡片网格 + 少量弹层），React 收益低；若后续 UI 复杂度明显上升（成就系统、多语言、对战大厅等），届时引入 React 重构外壳，游戏本体不受影响。

### 统一 Game 接口

```ts
interface Game {
  meta: { id: string; name: string; icon: string };
  mount(container: HTMLElement, ctx: GameContext): void; // 挂载并开始
  pause(): void;
  resume(): void;
  destroy(): void; // 离开时清理循环/监听器
}
// GameContext 提供：input、audio、storage、resize 通知
```

### 分层原则

**游戏逻辑与渲染分离**：每款游戏的规则写成纯函数模块（如 `tetris/logic.ts`），Canvas 渲染只消费状态。单测只测逻辑，不碰 DOM。

## 5. 视觉风格

**复古街机风**（四方案比选后用户选定）：

- 暗底（近黑深蓝紫）+ 霓虹描边（绿/品红/青/黄）+ 像素感字体。
- 首页为"GAME CENTER"卡片网格，每款游戏一张霓虹描边卡片（图标 + 名称 + 最高分）。
- 风格常量集中在 `core/theme.ts`，游戏内配色从主题取。

## 6. 操控方案

电脑：键盘（方向键/WASD/空格等常规映射）+ 鼠标。

手机（**按游戏定制**，三方案比选后选定）：

| 游戏 | 手机操控 |
|------|---------|
| 贪吃蛇 | 滑动手势转向 |
| 俄罗斯方块 | 精简按键条（左移/右移/旋转/速降/硬降） |
| 打砖块 | 拖动挡板 |
| Flappy Bird | 点按跳 |
| 2048 | 滑动 |
| 扫雷 | 点开格、长按插旗 |
| 数独 | 点格 + 数字键盘面板 |
| 五子棋 | 点格落子 |

响应式布局：手机竖屏优先，Canvas 按容器缩放，`GameContext` 下发 resize 通知。

## 7. 各游戏实现要点

- **贪吃蛇**：网格制；速度随分数渐增。
- **俄罗斯方块**：标准 7 种方块 + 7-bag 随机；软降/硬降；消行计分；下一块预览；Hold 暂存块（每次落块限用一次）。核心逻辑沿用作者早前一版已验证的实现（旋转公式、消行、几何重力曲线），呈现层按本项目街机风重做。
- **打砖块**：多关卡砖块布局；球速渐增；挡板反弹角度随击中位置变化。
- **Flappy Bird**：管道随机高度，碰撞即结束；实现最简单，**最先做完用于验证整体架构**。
- **2048**：4×4 滑动合并；支持撤销一步；达成 2048 后可继续。
- **扫雷**：初级/中级/高级三档；首点必不踩雷。
- **数独**：程序生成题目、保证唯一解，按难度三档；笔记模式；错误高亮开关；进行中盘面持久化。
- **五子棋**：15×15 标准盘；双人同屏 + 人机。

### 五子棋 AI（全项目技术重点）

- 启发式评分 + 极小极大搜索（α-β 剪枝，深度 2-4 层）。
- 评分函数识别棋形：活四、冲四、活三、眠三、活二等，按威胁度加权。
- 三档难度：简单（仅评分贪心）、中等（搜索 2 层）、困难（搜索 4 层 + 候选点剪枝）。
- 搜索运行在 Web Worker 中，避免阻塞 UI。

## 8. 音效

- `core/audio.ts` 用 Web Audio 振荡器实时合成 8-bit 短音效（方波/三角波），零音频素材。
- 关键动作触发：吃食物、消行、落子、合并、爆雷、胜利/失败等。
- 全局静音开关位于游戏外框标题栏，状态持久化。
- 首次用户交互后才初始化 AudioContext（浏览器自动播放策略）。
- 不做背景音乐（范围外）。

## 9. 数据存储

- `core/storage.ts` 封装 localStorage，统一前缀 `arcade.*`（如 `arcade.best.<gameId>`、`arcade.muted`）。
- 存储内容：各游戏最高分/最佳纪录、静音设置、数独进行中盘面。
- 所有读写 try-catch 兜底；localStorage 不可用（如隐私模式）时降级为内存存储，游戏功能不受影响。

## 10. 错误处理

- 外框对 `Game` 生命周期调用包 try-catch；单款游戏崩溃显示街机风"游戏出错"画面 + 返回首页按钮，不拖垮整个应用。
- `destroy()` 必须清理定时器、requestAnimationFrame、事件监听器，防止游戏切换后残留。

## 11. 测试

- **Vitest 单测**（针对纯逻辑）：俄罗斯方块消行/旋转踢墙、2048 合并、扫雷展开与首点安全、五子棋棋形评分与 AI 走子、数独生成唯一解等。
- **Playwright 冒烟**：首页 8 张卡片可见；每款游戏可进入且 Canvas 有渲染；返回首页正常。
- 开发流程：分支开发 → `tsc` → Vitest → Playwright → 英文 commit → `merge --no-ff` 到 main（→ push，仅在远程仓库建立后）。

## 12. 部署

- GitHub Pages；GitHub Actions 在 push 到 main 时构建发布。
- Vite `base` 配置为仓库名路径。
- **部署时机由用户决定**：开发期全程本地调试（Vite dev server，手机可经局域网试玩）；仅在用户明确确认"可以上线"后，才创建 GitHub 远程仓库并配置 Pages。上线后不 push 即不更新线上版本。

## 13. 范围外（明确不做）

在线对战、排行榜服务器、账号系统、背景音乐、多语言。

## 14. 建议实施顺序

1. 脚手架：Vite + TS + 外壳（路由/首页/外框）+ core 各模块。
2. Flappy Bird（最简，验证 Game 接口与移动端适配）。
3. 贪吃蛇 → 2048 → 打砖块 → 扫雷 → 俄罗斯方块 → 数独 → 五子棋（AI 最后、难度最高）。
4. 全局打磨：音效补全、Playwright 冒烟、README 与作品集说明。
5. 部署上线（仅在用户确认后执行）：创建 GitHub 仓库、配置 Pages 与 Actions。
