# 2026-09-13 社交预览图（GitHub Social preview）

## 背景

GitHub 在链接卡片里展示的 Social preview 是固定 2:1（推荐 1280×640）。直接上传首页截图
（2880×2336，约 1.23:1）会被居中裁掉标题和底部一排卡片。而首页截图本身只讲「品牌」，
看不出「8 个游戏」。

## 决定

- **用 8 个游戏的实机画面拼马赛克**，而不是「招牌 + 8 张机柜卡」。两版都做了并在推特卡片
  （600×300）与 Slack 缩略（360×180）尺寸下比较：机柜卡缩小后是八个一样的白框；马赛克缩小后
  仍能看出「上排四块黑屏、下排四块棋盘」。
- 产物进仓库：`docs/screenshots/social.png`（2880×1440），与其他展示素材放一起；生成脚本
  `scripts/social-preview.mjs`（`npm run social`）。GitHub 上传的那份只是展示副本，源文件与
  脚本在仓库里才能重出。
- 卡片用页面自己的字体与色板渲染（Bungee 标题、墨线边框、硬投影），色值镜像自
  `src/styles/arcade.css` 的 `:root`，脚本里有注释钉住来源。
- 深色四款是竖屏，格子里 `cover` 裁切：Breakout 对齐顶部保留砖墙，Tetris 对齐底部保留堆叠。
  纸盘四款是正方形，`contain` 完整放下，格子底色取各自的纸色。
- 游戏名放在格子下方而不是压在画面上，避免盖住棋盘格。

## 实现上的取舍

- **8 个游戏的驱动函数从 `scripts/record-games.mjs` 抽到 `scripts/game-drivers.mjs`**，
  录 GIF 与出社交图共用；预置分数也一并抽出，Snake 从 3840 改成 38，与首页截图一致。
- **实时类四款用 DPR 1 抓拍。** 驱动靠每 40 ms 读整张画布找精灵来操作，DPR 2 下像素量四倍，
  转向指令赶不上步进，蛇会直接撞墙。纸盘四款没有这个问题，用 DPR 2。
- **Snake 的死活用 DOM 判。** 结算面板是 `.settle` 浮层不是画在 canvas 上，读画布像素永远
  判不到；用 `.settle` 的 `hidden` 属性。抓拍策略是每 0.4 s 存一帧，浮层出现即停，取最后一帧。
- 其余实时游戏按固定时刻抓拍（结算出现之前）；Gomoku 在第五子落下前抓，避免 BLACK WINS 弹层。
